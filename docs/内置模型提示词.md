# DeepSeek 内置提示词与团队职责

当前版本为 `guandan-team-v3`。内置实现位于 [llm_prompts.py](../guandan_ai/llm_prompts.py)，调用与输出验证位于 [llm.py](../guandan_ai/llm.py)。所有兼容模型共用团队提示词，密钥仍只在服务端配置。

## 每个 Agent 的功能

每个模型是一名独立牌手。它只看自己的手牌和公开事实，不能读取队友或对手真实手牌，也不以斗地主的地主/农民角色进行决策。

| 当前局面 | 注入的职责 | 策略要点 |
|---|---|---|
| 座位身份 | 明确本人、对家队友和左右对手的绝对座位 | 0/2 一队，1/3 一队；不使用网页旋转后的座位推断关系 |
| 队友持有牌权 | 配合让牌 | 优先评估 PASS；只有本人直接收尾、可执行接管或明确团队收益才压队友 |
| 对手持有牌权 | 争取控制与必要拦截 | 比较压牌成本；对手剩1至2张时重点检查其下次出完机会 |
| 本人领出 | 组织手牌与团队推进 | 对手剩1张时谨慎送低单，剩2张时谨慎送小对子；不知道队友牌值就不假定其必能接牌 |
| 队友已出完 | 争取本人后续名次 | 不再向空手队友送牌，结合对手剩余牌和收尾能力安排控制资源 |
| 进贡、还贡 | 合法交接与保留结构 | 不套用跟牌或抢牌权策略，交接对象和合法范围由裁判决定 |

这些是策略指导，不是强制“队友领先一定不出”或“对手少牌一定炸”。模型仍需比较直接出完、队友掩护、后续控制和对手接牌机会。

## 内置规则说明

提示词解释两副牌、级牌、红桃级牌百搭、大小王编码、普通牌型、炸弹和同花顺，以及三带二和序列的比较要点。涉及合法性、抗贡、交接范围、接风和名次升级时，裁判提供的候选与结算是最终依据。

当前动作列表含 PASS 才按跟牌理解；领出列表即使带着上一阶段的旧 `greaterAction`，也不会错误提示模型“队友正在领先”。序列中的级牌按自然点数理解，模型不得自行重组或生成动作。

动作与交接契约来源：[课程官方平台](https://github.com/GameAI-NJUPT/OpenGuanDan)。具体规则由仓库下载并校验的固定版本运行时提供。

## 候选与局面说明

除原始动作外，每个候选附有：

- 中文牌型、出牌张数和是否能直接出完。
- 出牌后的本人手牌和结构粗估。
- 百搭消耗、是否使用炸弹等控制牌型。
- 是否拆开天然四张同点组、对子或三张。
- 本地启发式分数，明确标注为近似提示而非精确最优值。

候选裁剪额外保留各牌型的低代价代表，使模型可以选小牌压牌或改变领出牌型，避免只有评分靠前的高消耗动作。仍受配置的候选上限约束；小上限无法保留所有牌型。

公共历史只传递明确的公开出牌/交接字段，不直接转发任意原始消息。已出完的对手不会触发“少牌危险”警报。PASS 只作为行为信息，不被当作“绝对没有大牌”的证据。

## 输出、版本与调整

返回格式保持一个 JSON 对象：`{"candidate_id": 7,"intent":"improve_structure"}`。意图字段为可选的有限枚举，仅显示对应短标签；不出时提示模型说明让牌或保留控制的意图。编号须存在于本次候选中；格式错误、非法编号、空输出或超时仍合法回退。推理文本不保存或公开，只记录供应商返回的推理 token 数、`prompt_version` 和动作分类。

修改 `RULES_PROMPT` 可调整共用规则和策略，修改 `system_prompt()` 可调整动态职责，修改 `candidate_detail()` / `build_context()` 可调整提供给模型的事实。牌桌每个远程回合都新建隔离子进程，因此本机源码更新后，后续模型回合会加载新提示词；已发出的请求使用其开始时版本。其他长驻客户端重新启动后加载修改。

更详细的上下文和开启思考会增加 token 用量。本版默认开启 high 强度思考，请求上限45秒，推理加最终输出最多8192 tokens；可以通过环境变量调整，或切回 disabled / 512 的快速模式。服务器另外为子进程启动预留20秒和收尾余量，不把启动时间误当作模型思考超时。

v3 将保留候选按本地评分排列，不再固定让 PASS 成为编号0；额外标注不拆组合、不用百搭或炸弹的低成本跟牌候选。提示模型在对手持牌时认真比较这些选择，同时保留合理的队友让牌。有合法动作可以直接出完时，服务器直接选择该动作，不请求模型。统计区分唯一合法 PASS、队友持牌时不出、对手持牌时主动不出及异常回退；旧日志未分类的动作不被猜测归类。

## 本次验证

- 自动检查覆盖四座位的队友关系、领出旧牌权、交接阶段、已完成队友、拆牌标记、低代价候选保留和公共历史字段过滤。
- 真实小样本使用官方生成的合法动作：队友领先且剩2张时返回 PASS；对手领先且剩1张时返回小王牌压牌。两次均为 `guandan-team-v2`，无回退，合计4,660 tokens。
- 这些例子只验证接口与指定局面行为，不证明稳定胜率提升。正式比较需要固定牌堆换队、多场完整比赛，同时记录耗时、token 和回退率。

v3 开启高强度思考后的三个微局面都返回合法动作且无回退：队友领先时 PASS（约3.7秒、412推理 tokens），对手剩一张时小王拦截（约12.6秒、1906推理 tokens），普通对手领出时用黑桃6低成本跟牌（约7.3秒、1109推理 tokens）。这些是微局面验证，不能代替完整棋力评测。
