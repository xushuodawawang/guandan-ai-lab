# 联机与大模型对手方案

## 实现状态（2026-10-13）

共享房间、四个座位、准备、真人与本地/大模型 AI 混合设置、私有 WebSocket 推送、服务器 AI 调度、超时托管、断线重连、SQLite 重启恢复及通用模型适配器已实现。真实 DeepSeek 对战需要配置供应商密钥；本次仅用本机模拟服务验证，没有调用付费 API。Docker/HTTPS 部署模板已提供，尚未发布到公网。具体操作见 [联机使用与模型配置](联机使用与模型配置.md)。

以下保留设计依据与实施前的差距描述。

## 本次完成的选牌改进

手牌改为不重叠的网格，整个牌面都是点击区域。选中只改变边框和勾选标记，不抬起或移动卡片，因此相邻牌的点击位置不会变化。桌面、窄屏和手机自动换行；重复的两张实体牌保留独立编号。

上方点数按钮支持批量选同点数牌，再点可取消这一组。下方已选清单支持逐张移除；提示、合法牌型解释和服务器校验继续沿用。

## 实施前的架构与联机差距

现有 HTML/CSS/JavaScript 前端通过本机 JSON API 调用官方裁判，裁判保存实际手牌、计算合法动作并结算。浏览器只得到本人手牌和公开信息。这适合继续扩展。

目前的 `RoomService` 以浏览器 Cookie 区分独立单人牌局；`HumanGame` 固定真人为座位 0，AI 的行动由浏览器发起。本机服务仅监听 `127.0.0.1`。它尚不是四位玩家可以加入的共享房间，直接开放端口不能完成联机。

建议先实现局域网房间，再考虑公网部署：

| 阶段 | 要实现的行为 | 验收重点 |
|---|---|---|
| 共享裁判 | 将牌局从固定真人座位改为四个可配置座位，支持真人或 AI | 所有玩家共享同一牌局、随机牌堆和名次 |
| 建房入座 | 创建房间码、加入房间、选座、准备、房主开始，空位可补 AI | 座位不能被重复占用；四人入座后正常发牌 |
| 实时通信 | WebSocket 推送公共事件，私发本人手牌和合法动作 | 不能通过接口获取对手或队友的隐藏手牌 |
| 回合控制 | 裁判服务器推进回合，独立调度 AI 和超时托管 | 浏览器关闭或网络卡顿不阻塞整个牌局 |
| 断线恢复 | 玩家身份与房间座位绑定，重连取最新快照和事件序号 | 不能冒领座位，重复提交不能出两次牌 |
| 公网部署 | 配置服务器域名、HTTPS/WSS、身份与访问规则、日志和恢复 | 不把当前开发服务器直接当生产服务 |

命令应携带 `room_id`、当前 `revision` 和唯一 `command_id`。服务器先核对身份、行动座位和版本，再从官方动作列表执行。快照改为 `snapshot(room, viewer_seat)`，按观察座位过滤信息。现有版本校验可以复用，但 Cookie 必须绑定参与者身份，不能用一个 Cookie 代表全部玩家。

服务器 AI 调度应独立于浏览器。现有前端 `/api/ai` 由浏览器触发；多人版需由服务器在进入 AI 回合时自动提交任务，并在任务返回时再次核对回合版本。

## 接入 DeepSeek 等模型

可以复用现有策略协议 `observe(message)` / `decide(observation, budget_ms)`，增加大模型策略适配器。界面以后按每个座位配置“真人 / 本地 AI / 大模型 AI”，允许真人与大模型做队友，或大模型之间 PK。

推荐采用“本地生成合法候选，大模型选择动作”的方式：

1. 官方引擎提供完整合法动作，现有启发式按团队目标与手牌结构排序。
2. 从中提供有限数量的候选，保留 PASS、可以直接出完的动作以及必要的控制牌。候选裁剪会影响棋力，报告中需记录。
3. 仅发送该座位自己的手牌、级牌、公开出牌、各家剩余张数和带编号的候选。不能发送 `env` 的全局手牌或赛后完整日志。
4. 让模型返回 JSON，例如 `{"candidate_id": 7}`；编号对应此次请求的候选。
5. 校验 JSON 是否完整、编号是否为整数且存在、回合版本是否仍有效，再映射回原始官方动作。模型不能自行生成牌来出。
6. 超时、空响应、截断、解析失败、无效编号或供应商服务异常时，用本地 AI 合法回退，并记录原因。

DeepSeek 提供 JSON Output，可以使用 `response_format={"type":"json_object"}`，提示词中需明确要求 JSON 并提供格式示例。官方文档也提示可能出现空内容；JSON 格式有效不等于动作有效，仍需本地校验。[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)

其 Chat Completions API 也支持工具调用，可将选牌定义为函数参数，但依然应验证编号与当前回合。模型名称、功能和限制应按接入时的官方文档配置，不硬编码为长期固定值。[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)

建议的服务器配置字段：供应商、API 地址、模型名称、密钥环境变量名、请求超时、候选上限与回退策略。密钥只保存在服务器环境变量或服务端配置中，不写入浏览器 JavaScript、API 快照或 Git。

## 延迟、费用与公平比较

当前本地 AI 的预算约为 100ms。远程模型还有网络与推理耗时，不能直接套用同一预算。应为大模型使用单独的可配置期限，界面显示“正在思考”，在后台工作线程或进程请求，不能占用房间锁等待网络返回。任务携带回合版本，超时后的迟到结果必须丢弃。

大模型可能增加延迟和每手调用费用，是否强于现有 AI 需要实测；不能因为模型更大就宣称胜率更高。正式对照需记录模型版本、候选数、提示词版本、输入输出 token、费用、平均/P95 耗时、非法或超时回退率，并沿用固定牌堆换队和完整比赛统计。

## 推荐实现顺序

1. 完成共享房间与按座位过滤的裁判状态，支持局域网真人 + 本地 AI 混合对局。
2. 加入独立服务器 AI 调度、超时托管和断线重连。
3. 实现通用大模型策略适配器，先用模拟响应验证非法输出、空响应和超时回退。
4. 配置供应商密钥与模型后再进行真实 API 试打，随后跑配对评测。
5. 需要公网时，再做正式部署。

方案已落实为共享房间和模型接口。2026-10-13 用户授权配置密钥后，已通过 DeepSeek 官方接口鉴权与一次真实掼蛋决策验证；该验证会产生供应商用量。完整模型比赛评测和公网部署尚未进行，公网仍需要服务器、域名与证书。具体使用方法见 [联机使用与模型配置](联机使用与模型配置.md)，验证证据见 [验证记录](../reports/verification.md)。
