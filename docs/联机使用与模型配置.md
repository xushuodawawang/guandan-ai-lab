# 联机使用与模型配置

## 启动与邀请

Python 3.11+、JDK 17+，先按 README 下载官方运行时。然后在项目目录运行：

```powershell
python -m guandan_ai play --host 0.0.0.0 --port 8502 --ws-port 8503 --store data/server/rooms.sqlite3
```

本机打开 http://127.0.0.1:8502/ 。同一局域网的朋友使用服务器的局域网 IP，例如 `http://YOUR_LAN_IP:8502/`。网页和实时同步分别使用 8502、8503；其他设备无法连接时，检查网络是否互通、程序是否获准专用网络入站。不需要更改电脑的全局防火墙设置。

1. 输入昵称，点击 **创建联机房间**。
2. 分享六位房间码或 **复制邀请链接**。链接中的主机地址必须是朋友能访问的地址；`127.0.0.1` 仅指访问者自己的电脑。房主可先用局域网 IP 打开网页再复制邀请链接。
3. 朋友输入房间码，选择空位加入。实际座位 0 / 2 同队，1 / 3 同队。每个人看到的牌桌都以本人在下方、对家在上方排列。
4. 真人点击 **准备**，房主点击 **开始对局 · 空位补 AI**。房主可以把空座位设置为休闲、团队、综合 AI 或已配置的大模型。不能替换已经入座的真人。
5. **快速单人对局** 保留原玩法，你与三个 AI 直接开局。

同一浏览器的标签页共享一个身份。四个玩家应使用不同设备、不同浏览器或独立无痕会话。

## 自动推进、托管和恢复

- AI 由服务器调度，关闭某个浏览器不会停止 AI 的回合。
- 真人默认每回合 90 秒。超时后该座位自动托管，可以点击 **取消托管** 接回操作。命令行 `--turn-timeout 120` 可改变回合时间。
- 单人房间可暂停 AI 或单步观察；多人房间不能暂停整桌。
- 刷新、WebSocket 断线后重连仍回到原座位。实时通道不可用时退回 HTTP 同步，实时连接恢复后继续使用推送。
- SQLite 保存房间、身份哈希、初始牌堆种子和动作轨迹。服务器重启后重放轨迹恢复牌局，给当前回合重新计时。
- 原座位恢复依赖浏览器身份 Cookie。清除 Cookie 或更换浏览器会成为新身份，不能仅凭昵称冒领旧座位。
- 每副结束后可导出复盘。对局仍在进行时不公开完整手牌；导出还会去掉活跃比赛的发牌种子，避免据此预测后续牌堆。

`data/server/` 是服务器私有检查点，不由网页静态服务提供，且已加入 Git 忽略。它包含裁判数据，应与公开报告分开保存。API 密钥不保存在这个数据库中。

## 配置 DeepSeek

密钥只在运行服务器的环境变量或本地 `.env` 中设置。命令行启动时自动读取项目目录下的 `.env`，已有环境变量优先；该文件不会提交到 Git、进入 Docker 构建或提供给前端。设置后重启服务器，浏览器里的 DeepSeek 选项才会显示为已配置。

复制仓库的 `.env.example` 为 `.env`，在本机编辑密钥，后续直接运行启动命令即可。默认使用 `deepseek-flash`，牌桌请求关闭思考模式以便在有限回合时间内返回候选编号。[DeepSeek 思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)。可设置 `DEEPSEEK_THINKING=enabled` 开启，同时应增大回合预算；其他兼容服务的 profile 可省略 `thinking`，不发送该扩展参数。

```powershell
$env:DEEPSEEK_API_KEY = '填入你的 API 密钥'
$env:DEEPSEEK_MODEL = 'deepseek-flash'
$env:DEEPSEEK_TIMEOUT = '12'
python -m guandan_ai play --host 0.0.0.0 --port 8502 --ws-port 8503
```

模型名称应选择供应商账户实际可用的模型；示例名称来自当前官方 JSON Output 文档。[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)

创建房间后，把一个或多个空座位改成 **DeepSeek**，再开始。回合中显示“正在思考”，接口失败、空内容、非法候选编号或超时均会回退到本地合法策略。未配置密钥时，DeepSeek 选项不可选，也不会自动尝试付费请求。

模型只收到自己的手牌、公开出牌、剩余张数和有限数量的官方合法候选。返回 `{"candidate_id": 7}` 后，服务器再次验证候选并映射回官方动作。前端拿不到 API 密钥，也拿不到其他玩家的隐藏手牌。

## 其他兼容接口与计价

复制 `configs/llm.example.json` 到自己的配置文件，按需要加入多个 profile。供应商需支持同格式的 Chat Completions 和 JSON 输出。

```powershell
$env:GUANDAN_LLM_CONFIG = 'configs/llm.json'
python -m guandan_ai play --host 0.0.0.0
```

每个 profile 配置 `id`、`label`、`base_url`、`model`、`key_env`、`timeout`、`candidates`。密钥本身仍放在 `key_env` 指定的环境变量，不写入配置 JSON。远程地址用 HTTPS；本机兼容接口可用 `http://127.0.0.1:端口/v1`。

可选的 `input_price_per_million`、`output_price_per_million` 是用户配置的每百万 token 单价。未配置时费用显示未知。估算不包含供应商缓存折扣等特殊计价，实际以账单为准。超时且未收到用量返回的请求无法准确计价。

页面的 **AI 与模型调用统计** 显示动作数、回退数、模型回合、已收到的 token、平均/P95 耗时和估算金额。逐场日志记录模型名称、提示词版本、候选数量和失败原因。

## 与本地 AI 做 PK

配置好环境变量后，可使用已有固定牌堆换队评测：

```powershell
python -m guandan_ai evaluate --a llm:deepseek --b hybrid --pairs 2 --mode episode --strict-budget --budget 15000 --output data/runs/deepseek-smoke
```

此命令会实际调用模型并产生供应商费用。先用小样本检查，再决定正式评测规模。15000ms 是示例的双方单步预算；可以调整。正式比赛使用 `--mode match`，报告区分完整比赛与单小局；模型用量和回退单独记录。未运行真实 DeepSeek 比赛前，不声称它强于已有 AI。

## Docker 与公网

提供 `Dockerfile`、`compose.yaml` 和 `deploy/nginx.conf.example`。Docker 引擎运行后：

```powershell
docker compose up --build -d
```

Compose 将 8502、8503 映射到主机，并把 `data/server/` 挂载为持久化目录。环境变量可通过本地 `.env` 配置，该文件已忽略，不进入构建上下文。Compose 配置语法已验证；本次环境的 Docker 引擎未运行，镜像构建和容器运行尚未实测。

公网部署需要你自己的服务器、域名和真实 HTTPS 证书。Nginx 模板中替换 `YOUR_DOMAIN`，再配置：

```text
GUANDAN_PUBLIC_WS_URL=wss://YOUR_DOMAIN/ws
GUANDAN_COOKIE_SECURE=1
```

公网不需要将 SQLite 文件或 API 密钥提供给客户端。当前提供的是部署模板，本次没有替你发布到公网。
