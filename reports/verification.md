## 调整过的平台兼容问题

1. 官方 Python 的固定 deck_data 构造方式会留下空的内部重洗牌牌堆：通过创建完整内部牌堆后注入首局固定牌堆规避，未修改第三方文件。
2. 原生版的 userNum 不应一律当作实际座位：按顺序加入，以 beginning.myPos 校验。
3. 还贡后旧 greaterAction 可能保留：以当前合法动作列表是否含 PASS 识别领出，保留原始消息用于审计。
4. 原生 victoryNum 是小局头游计数；只有 victory，或已识别的 Python victoryNum/draws 结构，才用于完整比赛结果。

同学的客户端或比赛房间尚未提供，因此没有虚构同学 PK 结果。在线入口和外部策略插件已经实现。
